# JOURNAL_SETUP — 日记自动化（通用模板）

> 每日一问 + 每周复盘是人格档案的"主观层"输入：事件流记录发生了什么，
> 日记记录当事人怎么看。答案落 `persona/journal/YYYY-MM.md`，其
> `## 待折叠` 小节是夜间蒸馏的输入之一（消化后清空）。
> 建议排在夜间蒸馏之后（答案可被当夜折叠）或独立时段。

## 每日一问（每晚一次，推荐固定时刻）

提示词模板（对运行 agent 的 LLM 说）：

```text
无人值守日记任务。读取 {{PERSONA_HOME}}/persona/journal/{{YYYY-MM}}.md，
围绕今天的事件流（python eval/search_events.py 检索当日）回答一个问题：
- 从低置信池或 questions_pool.md 取一条今天有相关事件的，求证或推翻它；
- 否则取今日最值得记的一个决定/挫折/高光，按
  「发生了什么 / 我为什么这么做 / 与既有画像哪里一致或矛盾」三段作答。
答案写入当日 journal 文件的日期小节；若答案隐含档案修正，
在文末追加「## 待折叠」小节列出（条目 + 建议动作），交给夜间蒸馏消化。
字数 ≤300，不写废话。
```

## 周日五问（每周一次）

五个固定维度，每周轮换着答（不是每次全答）：

1. **本周画像漂移**：哪条 policy/belief 被本周行为支持或削弱了？
2. **线头复核**：open 线头逐一过一遍——还在推进吗？该闭合的最弱是哪条？
3. **关系与人物**：本周与谁的合作模式有新信息值得回写 people.yaml？
4. **记忆对账**：抽查低置信规则与超期 beliefs（对比 evidence 链与近期事件），
   被现实打脸的走 invalidate 流程；
5. **元问题**：蒸馏本身哪里烦了/错了？（折叠规则的修订意见也来自这里）

## 契约（与 schema 一致）

- journal 文件按月分片：`journal/YYYY-MM.md`；每答一段以 `## YYYY-MM-DD` 开头。
- `## 待折叠` 小节是**唯一**给夜间任务的通道；其余内容蒸馏不得改写。
- 日记是主观陈述，入库画像时仍须回到事件流找证据——两层的张力本身
  可以进 beliefs 的 `tension` 字段（记录，不仲裁）。
